# Task 4 Report: PDF invoices (and other voucher PDFs)

## Status
**Complete**

## Summary
Voucher PDF footers now read the supervisor phone from `PrintSettingsRepository` (Firestore-backed) instead of a hardcoded labeled string. The footer label is applied centrally via `formatSupervisorLine`.

## Changes

### `shared_pdf_template.dart`
- `supervisorContact` is now `PrintSettings.fallbackSupervisorPhone` (number only).
- `buildFooter` uses `formatSupervisorLine(supervisorPhone)` instead of inline `startsWith('supervisor')` logic.

### `voucher_pdf_service.dart`
- `defaultSupervisorPhone` points to `PrintSettings.fallbackSupervisorPhone` (removed dependency on `SharedPdfTemplate` for the default).

### `voucher_pdf_bloc.dart`
- Injects `PrintSettingsRepository`.
- Passes `supervisorPhone: printSettings.supervisorPhone` into `generateVoucherPdf`.

### `voucher_pdf_actions_widget.dart`
- Wires `PrintSettingsRepository` from context into `VoucherPdfBloc`.

### Per-template defaults (6 files)
- `invoice_pdf_template.dart`, `sales_order_pdf_template.dart`, `sales_return_pdf_template.dart`, `receipt_pdf_template.dart`, `expense_pdf_template.dart`, `stock_transfer_pdf_template.dart`
- Default `supervisorPhone` arg changed from labeled const to `PrintSettings.fallbackSupervisorPhone`.

### `test/voucher_pdf_service_test.dart`
- Added `VoucherPdfService - supervisor footer` group with two tests:
  1. Explicit `+971 50 999 0000` generates valid PDF bytes; `formatSupervisorLine` produces expected label.
  2. Default (no override) generates valid PDF bytes; `defaultSupervisorPhone` matches fallback.

## Self-review

### What works well
- Single source of truth: `formatSupervisorLine` handles both raw numbers and pre-labeled strings.
- `PrintSettingsRepository.supervisorPhone` already applies fallback when cache/Firestore is empty.
- All six voucher templates share the same footer path through `SharedPdfTemplate.buildFooter`.
- No thermal ESC/POS or Settings UI changes (deferred to Tasks 5/6).

### Limitations
- PDF footer text is Flate-compressed in generated bytes; unit tests assert `formatSupervisorLine` output and successful generation rather than parsing PDF streams.
- No `VoucherPdfBloc` unit test yet (brief noted none exists); wiring is covered indirectly via repository interface and widget DI.

### Not changed (by design)
- `esc_pos_ticket_builder.dart` — Task 5
- Settings UI — out of scope
- `voucher_pdf_repository.dart` — interface already had `supervisorPhone` param; no change needed
